# QUICK REFERENCE: Purchase Update Fix

## What Was Fixed
- ❌ UPDATE purchase returned **"Unauthorized"** error
- ✅ NOW works correctly with proper session validation

## Root Cause (One Sentence)
Old endpoint checked for session keys (`admin_id`, `pic_id`) that login endpoint **NEVER sets** (it sets `user_id` and `user_role` instead).

---

## Files Changed

| File | Change | Reason |
|------|--------|--------|
| `/api/barang/update-pembelian.php` | Changed from checking `admin_id`/`pic_id` to using `SessionValidator::requireRole()` | **MAIN FIX** - Match session keys set by login |
| `/api/barang/beli.php` | Added missing authentication check | Security - prevent unauthorized purchase creation |

---

## How It Works Now

```
User Login
    ↓
Sets: $_SESSION['user_id'] = 123
      $_SESSION['user_role'] = 'admin'
    ↓
User Edits Purchase + Clicks UPDATE
    ↓
Fetch with credentials: 'include' → sends session cookie
    ↓
Server: session_start() loads $_SESSION
    ↓
SessionValidator::requireRole(['admin', 'manager', 'pic_barang'])
    ↓
Checks: $_SESSION['user_role'] == 'admin' ✓
    ↓
UPDATE successful ✓
```

## Code References

### Before Fix (WRONG)
```php
if (!isset($_SESSION['admin_id']) && !isset($_SESSION['pic_id'])) {
    echo json_encode(["status" => false, "message" => "Unauthorized"]);
    exit;
}
```

### After Fix (CORRECT)
```php
require_once "../session-helper.php";
try {
    SessionValidator::requireRole(['admin', 'manager', 'pic_barang']);
} catch (Exception $e) {
    http_response_code(401);
    echo json_encode(["status" => false, "message" => "Unauthorized: " . $e->getMessage()]);
    exit;
}
```
