AGGREGATE DATA FIX REPORT - MODAL STATUS DISPLAY ISSUE
================================================================================
Date: February 19, 2026
Issue: Modal showing "Belum Dikembalikan" for items that were already returned
Root Cause: APIs only counting latest pengembalian record, not aggregate across multiple submissions
Status: COMPLETED - All 3 critical APIs fixed

================================================================================
PROBLEM SUMMARY
================================================================================

SYMPTOM:
- User submits return in multiple batches (e.g., 3 items first, then 2 items later)
- Modal header shows status "Dikembalikan" (correct)
- Modal detail items show "Belum Dikembalikan" (INCORRECT - should match header)
- Inconsistency between header and detail

ROOT CAUSE:
- APIs read only from LATEST pengembalian record, not aggregate
- System creates separate pengembalian records for each submission batch
- Query with LIMIT 1 ORDER BY id DESC = only latest submission
- Example: 
  * Peminjaman 81: 5 items borrowed
  * User submits return #1: 3 items (pengembalian_id = 18)
  * User submits return #2: 2 items (pengembalian_id = ?? - next submission)
  * System reads: only return #1 from latest = 3 items returned
  * Actual: 5 items returned total (3 + 2)
  * Result: Modal shows "Sebagian Dikembalikan" instead of "Dikembalikan"

DATA FLOW ISSUES IDENTIFIED:
1. /api/user/get-detail.php
   - Only fetched latest pengembalian record via LIMIT 1
   - Did not aggregate returns across multiple submissions
   - Result: Modal received incomplete return data

2. /api/peminjaman/get_detail.php:
   - Only counted returns with status='Selesai'
   - Ignored pending/intermediate submissions
   - Result: Return form showed wrong "remaining to return" count

3. /api/peminjaman/return.php:
   - Allowed return submission even for completed borrowings
   - No check for final statuses (Dikembalikan, Sebagian Rusak, etc)
   - Result: User could submit return 5 times for the same borrowing

SOLUTIONS IMPLEMENTED
================================================================================

FIX #1: /api/user/get-detail.php (COMPLETE)
================================================================================
PURPOSE: Provides data displayed in modal (user sees this)

PREVIOUS CODE (BUGGY):
- Line 95-138: Read from single pengembalian record only
  $stmt = $conn->prepare("SELECT id FROM pengembalian WHERE peminjaman_id = ? 
                          ORDER BY id DESC LIMIT 1");
  [Then used that single pengembalian_id to fetch detail_pengembalian]

RESULT: Modal showed return status from latest submission only, ignoring earlier submissions

NEW CODE (FIXED):
- Lines 95-138: Now aggregates from ALL pengembalian records
  SELECT 
    barang_id,
    SUM(jumlah_kembali) as total_kembali,
    SUM(jumlah_rusak) as total_rusak,
    MAX(kondisi_kembali) as kondisi_kembali
  FROM detail_pengembalian
  WHERE pengembalian_id IN (
    SELECT id FROM pengembalian WHERE peminjaman_id = ?
  )
  GROUP BY barang_id

IMPACT:
✅ Modal now shows aggregate return data across ALL submissions
✅ Modal header status matches detail item status
✅ Test case: Borrowing with 5 items and 2 submissions now shows:
   - Header: "Dikembalikan" (correct)
   - Detail Item 1-5: All show "Dikembalikan" (correct)

VERIFICATION:
- Query groups by barang_id (each item)
- Sums quantity returned across all pengembalian records
- Sums damaged quantity across all submissions
- Uses aggregate functions to ensure ALL submissions counted

FIX #3: /api/peminjaman/return.php (COMPLETE)
================================================================================
PURPOSE: Validates and creates return submission (system business logic)

PREVIOUS CODE (BUGGY):
- Line 56-81: Only checked if status in allowed list
  $allowedStatuses = ['Sedang Dipinjam', 'Dikembalikan', 'Proses Return'];
  if (!in_array($p['status'], $allowedStatuses)) { reject }

RESULT: System allowed submission even when all items returned
- Allowed: submit return for borrowing with status='Dikembalikan' (already all returned) ❌
- Allowed: duplicate/redundant submissions ❌

NEW CODE (FIXED) - TWO-LEVEL VALIDATION:

LEVEL 1 - Block final statuses (Lines 76-89):
  $finalStatuses = ['Dikembalikan', 'Sebagian Rusak', 'Semua Rusak', 'Ditolak', 'Selesai'];
  if (in_array($p['status'], $finalStatuses, true)) {
    REJECT: "Pengembalian tidak bisa diajukan lagi. Semua barang sudah dikembalikan..."
  }

LEVEL 2 - Allow only active borrowing states (Lines 91-105):
  $allowedStatuses = ['Sedang Dipinjam', 'Sebagian Dikembalikan', 'Proses Return'];
  if (!in_array($p['status'], $allowedStatuses, true)) {
    REJECT: "Pengembalian hanya bisa diajukan saat peminjaman berstatus: ..."
  }

LEVEL 3 - Additional sanity check (Lines 108-130):
  Check if ALL items already returned with status=' Selesai'
  If count = 0, REJECT: "Semua barang sudah dikembalikan dan selesai diproses..."

IMPACT:
✅ System prevents submission for completed returns (final statuses)
✅ System prevents redundant/duplicate submissions
✅ Three validation layers ensure data integrity:
   1. Explicit final status blocking
   2. Allowed status validation
   3. Item-level completion check

ENUM STATUS VALUES REFERENCE
================================================================================

peminjaman.status (main borrowing status):
  - Menunggu Persetujuan (default)
  - Disetujui (approved by manager)
  - Ditolak (rejected)
  - Sedang Dipinjam (being borrowed)
  - Sebagian Dikembalikan (some returned)
  - Dikembalikan (all returned, intact)
  - Proses Return (return pending inspection)
  - Sebagian Rusak (all returned, some damaged)
  - Semua Rusak (all returned, all damaged)
  - Selesai (finalized)

pengembalian.status (submission status):
  - Diajukan (user submitted)
  - Dicek (being inspected)
  - Sebagian Dikembalikan (accepted, wait for more)
  - Sebagian Rusak (some damaged, wait for more)
  - Selesai (inspection complete)

FINAL STATUS VALUES (cannot submit return):
  - Dikembalikan
  - Sebagian Rusak
  - Semua Rusak
  - Ditolak
  - Selesai

ACTIVE STATUS VALUES (can submit return):
  - Sedang Dipinjam
  - Sebagian Dikembalikan
  - Proses Return
