6. DATA FLOW VERIFICATION
================================================================================

PEMINJAMAN (Borrowing) Flow:
  1. User requests → api/user/request-peminjaman.php
     INSERT INTO peminjaman (status='Menunggu Persetujuan')
  2. Manager Review → api/approver/peminjaman-list.php
     SELECT FROM peminjaman WHERE status='Menunggu Persetujuan'
  3. Approve/Reject → api/approver/approve.php OR reject.php
     UPDATE peminjaman SET status='Disetujui'/'Ditolak'
  4. Admin Release → api/admin/update-status.php
     UPDATE peminjaman SET status='Sedang Dipinjam'
  5. User Returns → api/peminjaman/return.php
     INSERT INTO pengembalian, detail_pengembalian
     UPDATE peminjaman SET status='Proses Return'

PENGEMBALIAN (Return) Flow:
  1. User submits detail → api/peminjaman/return.php
     INSERT INTO pengembalian (status='Diajukan')
     INSERT INTO detail_pengembalian
  2. PIC retrieves list → api/pengembalian/list.php
     SELECT FROM pengembalian WHERE status='Diajukan'
  3. PIC reviews → Modal fetches api/pengembalian/detail.php
     SELECT FROM detail_pengembalian
  4. PIC confirms → api/pengembalian/inspect.php
     UPDATE pengembalian, detail_pengembalian
     UPDATE peminjaman status='Dikembalikan'
     UPDATE barang stok_tersedia, stok_rusak
  5. Final Report → api/pengembalian/damaged.php
     SELECT damaged items for reporting

All data flows from database, not hardcoded ✅
