TEST 2: API ENDPOINT VERIFICATION
================================================================================

Purpose: Verify APIs can retrieve data from database

Critical APIs to test in browser address bar:

TEST 2.1: Get all peminjaman
  URL: http://localhost/PROJECT/api/peminjaman/get_all.php
  Method: GET (just open in browser)
  Expected: JSON array with peminjaman records
  ✅ Pass if: Returns JSON with "status": true and array of records
  ❌ Fail if: Returns error or empty array

TEST 2.2: Get peminjaman by ID (new filter)
  URL: http://localhost/PROJECT/api/peminjaman/get_all.php?id=1
  Method: GET
  Expected: JSON with single record (if id=1 exists)
  ✅ Pass if: Returns 1 record in data array
  ❌ Fail if: Returns empty or error

TEST 2.3: Get peminjaman by Kode (new filter)
  URL: http://localhost/PROJECT/api/peminjaman/get_all.php?kode=PMJ-001
  Method: GET
  Expected: Single record matching that kode
  Note: Replace PMJ-001 with an actual kode from database
  ✅ Pass if: Returns matching record
  ❌ Fail if: Returns empty or error

TEST 2.4: Get barang details
  URL: http://localhost/PROJECT/api/user/get-detail.php?peminjaman_id=1
  Method: GET
  Expected: Items in that peminjaman
  Note: Replace 1 with valid peminjaman_id
  ✅ Pass if: Returns item array with nama_barang, jumlah, etc.
  ❌ Fail if: Returns empty or error

Expected Result: ✅ All APIs return JSON data from database

Troubleshooting:
  Empty array: Check if data exists in database
  JSON error: Check PHP syntax (`php -l api/file.php`)
  500 error: Check database connection in api/koneksi.php

TEST 4: FULL USER WORKFLOW
================================================================================

Purpose: Test entire system flow from request to completion

Prerequisites:
  [ ] Have test user accounts created
  [ ] Each user has different role (admin, manager, user, pic_barang)

STEP 1: User Requests Item
  As: REGULAR USER (nrp: 003 or similar)
  1. Login to: http://localhost/PROJECT/auth/login.html
  2. Navigate to: user/peminjaman/ajukan-peminjaman.html
  3. Select an item from barang list
  4. Enter quantity
  5. Click "Ajukan Permintaan"
  
  Expected:
     ✅ Request created successfully
     ✅ Can see it in user/peminjaman/status-peminjaman.html
     ✅ Status shows "Menunggu Persetujuan"
     ✅ Database updated (check phpMyAdmin)

STEP 2: Manager Reviews Request
  As: MANAGER user (nrp: 002 or similar)
  1. Logout previous user and login as manager
  2. Navigate to: manager/persetujuan/menunggu-approval.html
  3. Should see the new request
  4. Click approve
  
  Expected:
     ✅ Request status changes to "Disetujui"
     ✅ Appears in manager/persetujuan/disetujui.html
     ✅ Database updated

STEP 3: Admin Releases Items
  As: ADMIN user (nrp: 001 or similar)
  1. Logout and login as admin
  2. Navigate to: admin/peminjaman/data-peminjaman.html
  3. See the approved request
  4. Change status to "Sedang Dipinjam"
  
  Expected:
     ✅ Status updates to "Sedang Dipinjam"
     ✅ Database reflects change

STEP 4: User Submits Return
  As: REGULAR USER
  1. Logout and login as original user
  2. Go to: user/pengembalian/ajukan-pengembalian.html
  3. See the borrowed items
  4. Enter return quantities
  5. Submit return request
  
  Expected:
     ✅ Return request created
     ✅ Status shows "Proses Return" or "Diajukan"
     ✅ Database updated

STEP 5: PIC Inspects Return
  As: PIC_BARANG user (nrp: 004 or similar)
  1. Logout and login as PIC
  2. Go to: pic-barang/pengembalian/pengembalian-barang.html
  3. See return request waiting for inspection
  4. Click to inspect items
  5. Confirm conditions (good or damaged)
  6. Submit inspection
  
  Expected:
     ✅ Return status updates to "Sebagian Dikembalikan" or "Selesai"
     ✅ Barang stock is updated
     ✅ Any damage costs are calculated

Expected Result: ✅ Complete workflow works from user request to PIC confirmation

Troubleshooting:
  Page shows wrong status: Clear browser cache
  Database not updating: Check API response in browser console
  Authorization errors: Verify user role in database
  Missing records: Check if tables have foreign key relationships

  1. Open page in browser
  2. Press F12
  3. Click Sources tab

  Expected:
     ✅ NO lines like: const dataDitolak = [{...}]

================================================================================

Purpose: Verify proper security measures are in place

  4. Logout
  5. Try same URL again
  
  Expected:
     ✅ Redirects to login page
     ✅ Cannot view detail without valid session

TEST 6.2: Role-Based Access
  As: REGULAR USER
  1. Logout and login as regular user (not admin)
  2. Try to access: admin/dashboard.html
  
  Expected:
     ✅ Redirects to user dashboard
     ✅ Cannot access admin pages

TEST 6.3: SQL Injection Prevention
  At: api/peminjaman/get_all.php?id=1 OR 1=1
  
  Expected:
     ✅ Returns data for id=1 only (not all records)
     ✅ Query is parameterized, not vulnerable

TEST 6.4: XSS Prevention
  Try entering: <script>alert('XSS')</script> in any form
  
  Expected:
     ✅ Text displays safely as plain text
     ✅ Script does NOT execute
     ✅ No security popup

Expected Result: ✅ All security measures working properly

Troubleshooting:
  Session not validating: Check session-validator.js is loaded
  Access not restricted: Check page-guard.js role validation
  Script executed: Check HTML escaping in PHP/JavaScript
