**Issue:** "Unauthorized" error when updating item purchase

**Status:** 🟢 FIXED & VERIFIED

## 📋 WHAT WAS DONE

### 1. ROOT CAUSE ANALYSIS
Found that:
- ❌ LOGIN endpoint sets: `$_SESSION['user_id']`, `$_SESSION['user_role']`
- ❌ UPDATE endpoint checked: `$_SESSION['admin_id']`, `$_SESSION['pic_id']` (WRONG KEYS)
- ❌ Result: Always "Unauthorized" since wrong keys don't exist

## 🔑 HOW IT WORKS NOW

```
1. User logs in
   → $_SESSION['user_id'] = 5
   → $_SESSION['user_role'] = 'admin'

2. User edits purchase & clicks UPDATE
   → Fetch to /api/barang/update-pembelian.php
   → credentials: 'include' sends session cookie

3. Server receives request
   → session_start() loads $_SESSION
   → SessionValidator::requireRole(['admin', 'manager', 'pic_barang'])
   → Checks: Is user_role in allowed list?

4. Authorization check
   → ✅ YES (user is 'admin') → UPDATE database
   → ❌ NO (user is 'user') → Return 401

5. Response
   → {"status": true, "message": "Purchase updated successfully"}
   → Modal closes, table refreshes
```
